# Техническое задание: кооп-битэмап ко дню рождения

Версия 1.0 · 20.10.2026 · Основа: PRD v1.0 · Дедлайн 07.11.2026

Решения, принятые с PO 20.10:
- Домен для wss: бесплатный `<ip>.sslip.io`, без покупки и без резервного хостнейма (сбой sslip.io принят как риск).
- M-1 (офлайн-соло) остаётся в объёме за счёт общей симуляции для клиента и сервера.
- Генератор спрайтов выбирается тестом на этапе дизайна; ниже только требования к ассетам и критерии теста.

---

## 1. Стек (зафиксирован)

| Слой | Технология | Версия на 20.10.2026 | Зачем |
|---|---|---|---|
| Рендер, сцены, ввод | Phaser | 4.2.x (4.2.1 от 09.07.2026) | Готовые сцены, спрайт-анимации, мультитач, pixelArt-режим |
| Сетевой сервер | Colyseus | 0.18.x (0.18.9) | Комнаты, вход по id, синхронизация состояния, переподключение (`onDrop`/`allowReconnection`) |
| Клиент сети | @colyseus/sdk | 0.18.x | Пара к серверу 0.18; пакет `colyseus.js` устарел (0.16), не использовать |
| Схема состояния | @colyseus/schema | 5.x | Новый синтаксис `schema({...})`, без декораторов |
| Язык | TypeScript | актуальный | Общие типы между клиентом, сервером и симуляцией |
| Сборка клиента | Vite | актуальный | Статический `dist/` для GitHub Pages |
| Рантайм сервера | Node.js | 22 LTS или новее | Colyseus 0.18 требует `node >= 22` |
| Прокси и TLS | Caddy | актуальный | Автоматический Let's Encrypt, проксирование WebSocket без ручной настройки |
| Процесс-менеджер | systemd (или pm2) | | Автоперезапуск сервера после падения и ребута |

Отклонение от правила папки `games/` («vanilla JS, без сборки»): здесь нужны npm-зависимости и общий код клиент/сервер, поэтому Vite + TS. Шаблон `_template/` не подходит, проект создаётся с нуля, README по правилам папки.

Не используем:
- Arcade/Matter physics для логики боя: логика живёт в общей симуляции, Phaser только рисует.
- Клиентское предсказание Colyseus 0.18: PRD его не требует (T-5), это лишний риск. Держим как запасной вариант, если 200 мс окажутся неиграбельными.
- Плагин джойстика rexrainbow: совместимость с Phaser 4 не подтверждена ни одним найденным источником. Джойстик пишем сами (около 100 строк).

## 2. Архитектура

```
birthday-coop/
  shared/   чистая симуляция боя + контент (персонажи, уровни, реплики). Без импортов Phaser и Colyseus
  server/   Colyseus Room: оборачивает симуляцию, принимает ввод, отдаёт состояние
  client/   Phaser: сцены, рендер, ввод, звук; LocalSession и OnlineSession
  ops/      Caddyfile, systemd unit, инструкция развёртывания (T-8)
```

### 2.1 Общая симуляция (ключ к M-1 без удвоения кода)

| ID | Требование |
|---|---|
| S-1 | `shared/sim` экспортирует `createWorld(levelId, seed)`, `addPlayer`, `removePlayer`, `step(world, inputs, dtMs) -> events[]`. Чистые функции над plain-объектами |
| S-2 | Фиксированный тик 20 Гц (50 мс) и на сервере, и в офлайне. Рендер 60 fps отдельно |
| S-3 | Координаты: `x` вдоль уровня, `y` глубина дорожки, `z` высота прыжка. Сортировка спрайтов по `y` |
| S-4 | Попадание: `|dx| < range`, `|dy| < laneTolerance`, удар в сторону взгляда. Никакой физики и пиксельных хитбоксов |
| S-5 | Ввод игрока: `{ moveX, moveY, seq, pressed: {attack, heavy, taunt, ult, jump} }`. Кнопки как фронты нажатия, чтобы нажатие не терялось между тиками |
| S-6 | Случайность только через `seed` мира, никакого `Math.random()` внутри sim |
| S-7 | Разовые события (удар, реплика, ульт, смерть, смена волны) возвращаются из `step` списком; клиент по ним играет звук, вспышки, пузыри с текстом |
| S-8 | Юнит-тесты sim запускаются в Node без браузера: волна врагов убивается, ульт заряжается, поражение перезапускает уровень |

### 2.2 Две сессии, один рендер

| ID | Требование |
|---|---|
| A-1 | Интерфейс `GameSession { sendInput, onSnapshot, onEvents, leave }` |
| A-2 | `LocalSession`: крутит sim в браузере (M-1). `OnlineSession`: Colyseus Room (M-2…M-5) |
| A-3 | Сцены Phaser знают только снимок состояния и события. Ни одной ветки `if (online)` в коде рендера |
| A-4 | Переключатель «Онлайн-режим» (M-7) выбирает реализацию сессии и хранится в `localStorage` |

### 2.3 Сервер

| ID | Требование |
|---|---|
| N-1 | Одна комната `game`, `maxClients = 2`. Тик через `setSimulationInterval` 50 мс |
| N-2 | Состояние Schema: `players`, `enemies` (map: x, y, z, hp, anim, facing), `level`, `wave`, `phase`. Копируется из sim после каждого тика; позиции квантуются |
| N-3 | События sim рассылаются `broadcast`, не через Schema |
| N-4 | Вход по ссылке (M-6): хост создаёт комнату, ссылка `https://<user>.github.io/<repo>/#<roomId>`. Второй игрок открывает ссылку и делает `joinById` |
| N-5 | Подключение в середину (M-4): новый игрок появляется рядом с живым игроком в текущей волне; выбор персонажа на экране входа, занятые персонажи неактивны; уникальность проверяет сервер (P-2) |
| N-6 | Обрыв (M-5): `onDrop` → игрок заморожен и неуязвим, `allowReconnection(client, 60)`. Не вернулся за 60 с: удаляется, игра идёт соло |
| N-7 | Клиент хранит `reconnectionToken` в `sessionStorage` и делает `client.reconnect(token)` после возврата в Safari. Причина: хост уходит в мессенджер отправить ссылку, iOS рвёт сокет, автоматическое переподключение в этом случае не спасает (по документации Colyseus перезагрузка или смена приложения требует ручного режима) |
| N-8 | Если все игроки в комнате отвалились, sim ставится на паузу. Иначе хоста забьют враги, пока он шлёт ссылку |
| N-9 | Пустая комната удаляется через 2 минуты |
| N-10 | Эндпоинт `/health` для проверки перед вручением. Колизеевский monitor/playground в проде выключен |
| N-11 | CORS для матчмейкинга разрешает origin `https://<user>.github.io` (проверить в прототипе) |

### 2.4 Сетевое сглаживание (T-5, T-6)

| ID | Требование |
|---|---|
| L-1 | Клиент рисует чужих и себя с буфером интерполяции около 100 мс между двумя последними снимками |
| L-2 | Свой персонаж без предсказания. При 200 мс задержка ввода около 250 мс; для битэмапа с упрощёнными боями это терпимо, проверяется в прототипе |
| L-3 | Отладочный оверлей `?debug=1`: fps, ping (`room.ping()`), число активных касаний, id комнаты |
| L-4 | Тест задержки: Chrome DevTools throttling и `tc netem delay 200ms` на VPS |

## 3. iPhone и Safari

| ID | Требование | Почему |
|---|---|---|
| I-1 | Phaser config: `input.activePointers: 4` | Джойстик + кнопка + запас; по умолчанию касаний меньше |
| I-2 | CSS на canvas и body: `touch-action: none`, `user-select: none`, `-webkit-touch-callout: none`; viewport `width=device-width, initial-scale=1, maximum-scale=1, user-scalable=no, viewport-fit=cover` | Без двойного тапа на зум, лупы и выделения |
| I-3 | Кнопки и джойстик сдвинуты на `env(safe-area-inset-*)` | В горизонтали Dynamic Island перекрывает край экрана |
| I-4 | Портрет: оверлей «Поверни телефон», игра на паузе | Блокировка ориентации на iPhone недоступна: требует element fullscreen, а iPhone его не поддерживает (WebKit bug 257695; caniuse даёт Safari iOS только partial) |
| I-5 | Полноэкранный режим не обещаем. Опционально: `manifest.json` с `display: fullscreen` и подсказка «На экран Домой» | Home Screen web app даёт почти весь экран; проверить в прототипе |
| I-6 | Вёрстка от реальной видимой области (`100dvh`, `Scale.FIT`), проверка с панелью Safari внизу | Панель адреса съедает высоту в горизонтали |
| I-7 | Звук: разблокировка на первом касании (экран «Тапни, чтобы начать»), плюс `if ('audioSession' in navigator) navigator.audioSession.type = 'playback'` | Без этого Web Audio молчит при включённом беззвучном режиме (WebKit bugs 251532, 252746). Трюк с тихим зацикленным `<audio>` не использовать: в cat-piano-ultra пустой WAV вешал Safari |
| I-8 | Джойстик плавающий: появляется там, где палец коснулся левой половины. Кнопки: зона касания не меньше 64 pt, больше видимой иконки | Не промахнуться вслепую |
| I-10 | Взять готовое из `cat-piano/index.html`: viewport (стр. 5), сброс выделения и подсветки тапа (стр. 10–16, `100dvh`, safe-area), подавление зума `touchstart preventDefault` + `dblclick` + `gesturestart` (стр. 526–529), трекинг касаний `Map` по `pointerId` (стр. 493–524) | Проверено на опубликованной игре |
| I-9 | Джойстик 8 направлений (диагонали) вместо 4 из C-1 | В битэмапе подход к врагу по диагонали базовое действие; 4 направления будут ощущаться деревянно. Решение за PO |

## 4. Игровая логика: уточнения к PRD

| ID | Требование | Статус |
|---|---|---|
| G-1 | 3 уровня по 4–5 минут: 3–4 волны, камера двигается дальше после зачистки волны | Предложение |
| G-2 | Поражение: все живые игроки упали одновременно → перезапуск уровня. Упавший в коопе встаёт через 5 с, если напарник жив | Предложение, уточняет «поражение = перезапуск» из PRD |
| G-3 | Ульт: шкала копится от нанесённого урона, полная шкала = кнопка активна | Предложение для C-5 |
| G-4 | Ульты собираются из 4 архетипов с параметрами: удар по площади, рывок через экран, лечение/щит напарнику, оглушение всех врагов. 8 персонажей = 4 архетипа × разные числа, анимация и реплика | Снижает объём P-4 в разы |
| G-5 | «Унижение»: случайная реплика из списка персонажа, пузырь над головой 2 с, кулдаун 3 с. Урона нет | Как в PRD |
| G-6 | Враги: 2–3 типа (обычный, толстый, быстрый) + босс с 2 фазами. ИИ: подойти на дорожку игрока, ударить, отступить. Цель: ближайший игрок | Предложение |
| G-7 | Масштаб HP врагов при двух игроках ×1.5 | Баланс уточняется игрой (PRD, раздел 12) |
| G-8 | Финал: победа над боссом → сцена поздравления (текст, все персонажи, музыка) → пасхалка | Как в PRD |

### 4.1 Контент как данные

Всё, что пишет PO, лежит в `shared/content/` и правится без кода:
- `characters.ts`: имя, спрайт, скорость, урон, архетип ульта и его числа, массив реплик для «унижения».
- `levels.ts`: фон, длина, волны (тип врага, количество, точка срабатывания по `x`).
- `texts.ts`: экраны, поздравление, пасхалка.

## 5. Графика и звук

| ID | Требование |
|---|---|
| V-1 | Внутреннее разрешение 480×270 или 640×360 (16:9), `pixelArt: true`, масштаб целым множителем где возможно. Выбор по тесту генерации (P-7) |
| V-2 | Персонаж 48–64 px в высоту, вид сбоку, смотрит вправо; влево зеркалим (`flipX`) |
| V-3 | Набор кадров на персонажа. Минимум: idle 2, walk 4, attack 3, hurt 1, down 1. Желательно: heavy 3, ult 3, taunt 2, jump 2 |
| V-4 | PNG с прозрачностью, единая палитра и единая высота кадра для всех персонажей; спрайт-лист сеткой или атлас |
| V-5 | Фоны уровней: 1 широкая картинка или 2 слоя для параллакса на уровень |
| V-6 | Шрифт: пиксельный, с кириллицей, лежит локально. Кандидат Press Start 2P (наличие кириллицы проверить) или bitmap-шрифт |
| V-7 | Все ассеты локально в репозитории, источник и лицензия каждого в README (правило папки `games/`) |
| V-8 | Звук: спрайт-аудио (один файл + разметка) или до 20 коротких mp3; музыка: меню, уровень, босс |

Критерии теста генераторов (на одном персонаже, все варианты одним промптом):

| Критерий | Как проверяем |
|---|---|
| Узнаваемость силуэта и цветов друга | Показать без подписи паре человек |
| Персонаж одинаковый во всех кадрах | Прогнать walk в игре, смотреть на «плавание» лица и одежды |
| Чистая прозрачность, ровная пиксельная сетка | Масштаб ×4, без полупрозрачной каймы |
| Время на персонажа | Целевое: до 1 часа на полный набор кадров |
| Стоимость всего каста | Цена × 8 персонажей × число попыток |

Кандидаты из текущих данных:

| Инструмент | Что известно | Риск |
|---|---|---|
| PixelLab | Пиксель-нативный, персонажи и анимации ходьбы/бега/idle по тексту; около $12/мес (в одном источнике $10), пробные 40 генераций | Цена по сторонним обзорам, официальную страницу не открыл |
| Retro Diffusion | Пиксель-нативный, прозрачный фон, анимации, оплата за генерацию от ~$0.01 (данные самого проекта) | Самоотчёт, независимых тестов не нашёл |
| Genex image | Уже подключён: 7 кр (~$0.07) за картинку, `--transparent`, `--edit`; на балансе 134 кр, пополнение до 200 24.10 | Не пиксель-нативный, кадры анимации собираются через `--edit`, консистентность под вопросом |
| Genex sfx / music | 2 кр за эффект, 27 кр за трек | Промпт не управляет высотой и характером точно: в cat-piano одинаковый промпт давал мяу от 300 до 750 Гц. Заказывать пачкой 3–6 вариантов и выбирать на слух, страница сравнения как `sfx-test.html` |

Бюджет Genex на 20.10: баланс 134 кр, лимит текущего билда 100 кр, из них потрачено 66 (cat-piano-ultra), осталось 34. Поднять лимит `npx genex budget --assets <кр> --user-approved` только с согласия mr.R. Нет ffmpeg и sox: нарезка и обработка звука только в браузере или по байтам MP3, лучше сразу заказывать короткие отдельные файлы.

## 6. Хостинг и инфраструктура

| ID | Требование |
|---|---|
| H-1 | Клиент: GitHub Actions собирает Vite и публикует `dist/` на Pages. `base` в Vite равен имени репозитория |
| H-2 | Адрес сервера в клиенте задаётся через `VITE_SERVER_URL`, не захардкожен |
| H-3 | Сервер: VPS Amsterdam, Node 22+, systemd unit с `Restart=always`, Caddy впереди: `<ip-через-дефисы>.sslip.io { reverse_proxy localhost:2567 }`. Caddy сам получает сертификат Let's Encrypt (HTTP-01), нужен открытый порт 80 и 443 |
| H-3a | У Claude на VPS нет sudo. Установка Caddy, unit systemd, открытие портов 80/443 делает mr.R по готовому скрипту `ops/setup.sh` (одноразово, около 10 минут). Без этого шага H-3 невозможен |
| H-3b | Альтернатива без Caddy и sslip.io: Tailscale Funnel публикует `https://66164.tail9f6015.ts.net` в интернет с готовым сертификатом. Нужно: атрибут funnel в политике tailnet (админка, mr.R) и `sudo tailscale set --operator=agent` один раз. Риски: лимит трафика Tailscale не раскрывает (для 2 игроков трафик мизерный), WebSocket через Funnel подтверждён только косвенно, трафик идёт через релеи Tailscale (лишняя задержка, проверить пингом). Порт 443 уже занят `tailscale serve` под другие сервисы, игре брать 8443 или 10000 |
| H-4 | Страница на https требует wss, иначе браузер блокирует смешанный контент |
| H-6 | Проверка за день до и утром 07.11: `/health`, тестовая комната с двух телефонов, срок сертификата |
| H-7 | `ops/README.md`: развёртывание с нуля за 15 минут (T-8) |

## 7. Тестирование

| Что | Как | Когда |
|---|---|---|
| Логика боя | Юнит-тесты `shared/sim` в Node | С 24.10 при каждом изменении |
| Комнаты, вход, обрыв | Playwright: два браузерных контекста, вход по ссылке, закрытие одного, повторный вход | С прототипа |
| Мультитач, звук, safe area, ориентация | Реальный iPhone 15 Pro, чек-лист раздела 3 | 22–23.10, затем каждые 2–3 дня |
| Задержка 200 мс | `tc netem` на VPS, проход уровня вдвоём | 29.10 и 05.11 |
| Сценарий вручения | Ссылка из мессенджера → игра соло → второй входит в середине → один выходит → финал | 05–06.11 |

Ограничения среды (опыт cat-piano-ultra):
- MCP `playwright` на VPS не стартует (нет системных библиотек, нет sudo). Сетевые сценарии тестируем Node-ботом на `@colyseus/sdk` (два бота входят в комнату, один отваливается, проверяем состояние), UI смотрим через `cloudcli-browser`.
- Сессии `cloudcli-browser` с анимированной страницей грузят CPU VPS (около 50% в течение часа). Закрывать сессию сразу после проверки, игра на паузе в скрытой вкладке.
- Звук из браузера на VPS не слышно, звук и мультитач подтверждает только mr.R на iPhone.
- Есть MacBook в tailnet: Safari Web Inspector для iPhone доступен (кабель или Wi-Fi). Оверлей L-3 и вывод ошибок на экран (`window.onerror` → текст поверх игры) всё равно обязательны: на вручении Mac рядом не будет.

Цикл разработки: Vite dev-сервер и Colyseus слушают Tailscale-IP VPS, iPhone в tailnet открывает `http://100.118.72.60:<порт>` и `ws://` без деплоя и сертификатов. Деплой на Pages и wss только для приёмки. Сервер для раздачи только многопоточный (однопоточный python http.server вешался от пустых соединений Safari).
