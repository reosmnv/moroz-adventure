`client/src/main.ts`, `client/src/audio.ts`, `client/src/story.ts`, `client/src/ui.ts`, `client/src/stage.ts`, `client/src/settings.ts`, новый файл `client/src/debug.ts` (если нужен), `client/index.html`, `client/public/manifest.webmanifest`, `client/vite.config.ts`, `README.md`. ## Пункты
1. **bugs 12. Утечка сессии при ошибке запуска** (main.ts ~122). Если запуск падает после создания `LocalSession`/`OnlineSession.open()` или после создания игры, обработчик ошибки должен закрыть частично созданную сессию (её метод закрытия, посмотри в session.ts, не меняя его) и уничтожить созданную игру Phaser, чтобы повторный запуск не плодил вторую.
2. **bugs 13. Звук после возврата в Safari** (audio.ts ~20). Возобновлять остановленный/прерванный AudioContext на любом пользовательском жесте в игре (pointerdown/touchend/keydown на документе, capture, passive), а не только в меню. Дёшево: если контекст `running`, ничего не делать. Помни грабли: тихий зацикленный `<audio>` вешает Safari, не добавлять такой. Звук проверит только mr.R.
3. **bugs 14. Лишняя работа каждый кадр.** story.ts ~259: при печати реплики текст дважды за кадр меняется между полной и частичной строкой (видимо, для замера высоты). Кешировать высоту реплики (замер один раз на реплику/изменение ширины), текст обновлять только при изменении числа символов. ui.ts ~394: HUD каждый кадр измеряет DOM-границы (getBoundingClientRect) и переписывает размеры/позиции телефонной карточки. Кешировать, пересчитывать по resize/visualViewport.resize/orientationchange и при смене содержимого. Поведение на экране не должно измениться.
4. **legacy 3. Загрузка игры после меню.** `main.ts` статически импортирует `./scene.ts` (а через него Phaser): весь движок грузится уже для меню. Сделать `import('./scene.ts')` в момент запуска игры (после выбора в меню), меню должно работать без Phaser. Если в main.ts используются другие вещи из scene.ts/Phaser до запуска, обойди это без правки scene.ts (например, перенести в main.ts только то, что нужно меню, или тоже грузить лениво). В `vite.config.ts` убрать поднятый `chunkSizeWarningLimit: 2000` (вернуть предупреждение по умолчанию). В отчёте: размеры начального чанка и чанка игры из вывода сборки, до и после.
5. **legacy 22. Единый флаг debug.** main.ts проверяет `params.has('debug')` (тогда `?debug=0` включает панель), stage.ts требует `debug=1`. Один флаг в одном месте (например `client/src/debug.ts`: `export const DEBUG = new URLSearchParams(location.search).get('debug') === '1'`), использовать в main.ts и stage.ts. Доступность в релизе оставить (флаг только по URL).
6. **legacy 23. Название.** `client/index.html` `<title>НЕСУЩЕСТВУЮЩАЯ</title>` → `Moroz Birthday Adventures` (это `GAME_TITLE` из story.ts). Manifest: `name` «Moroz Birthday Adventures», `short_name` короткое (например «Moroz»). Других смысловых правок в index.html не делать.
7. **legacy 1 и 23. README.md.** Актуализировать верх README: описание (кооп-битэмап ко дню рождения на Phaser 4 + Colyseus + общая симуляция, до 4 героев, офлайн-соло и онлайн-комната; не «серый прототип, квадратики»), запуск для разработки без `ops/dev.sh` (он убивает процессы и может положить боевой сервер :2567): свой сервер `HOST=127.0.0.1 PORT=2568 node --import tsx server/src/index.ts`, клиент `cd client && node ../node_modules/vite/bin/vite.js --port <свой>`, тесты (`npx tsc -p tsconfig.json`, `node --import tsx server/src/<имя>-test.ts`, `SERVER_URL=http://127.0.0.1:2568 node --import tsx server/src/net-test.ts`); прямое предупреждение, что `ops/dev.sh` не запускать при работающем боевом. Управление переписать по фактическому коду (ui.ts, scene.ts, hero-data: какие кнопки есть сейчас на экране и какие клавиши в scene.ts) — проверь в коде, не выдумывай. Таблицу ассетов не трогать, кроме одного: в строке «Эффекты 06.11» убрать имя «Кати» (заменить «удар Кати по земле» на «удар босса по земле»): по STORY-V3 её имя не выносится в README.
